# omegese45 pipeline: data, core model, training

Pipeline lane of [aien-train#45](https://github.com/aien-dev/aien-train/issues/45). This lane owns:

- `native/omegese45/data/gen.om` (episode generator);
- `native/omegese45/core/{model,ckpt,run,cli}.om` (core model, checkpoint, training and decode CLI);
- `tests/omegese45/core/` (build, suite, oracle);
- the receipts under [`evidence/OMEGESE45/pipeline/`](../../evidence/OMEGESE45/pipeline/).

The vocabulary (R45, 41 ids), grammar, reference policy and exit codes belong to the contract lane
and are used unchanged (`native/omegese45/{vocab,msg}.om`, `docs/omegese45/vocab.tsv`). The command
line is documented in [CORE-CLI.md](CORE-CLI.md).

Status words: IMPLEMENTED (code exists), EXERCISED (run, with a receipt), NOT_RUN. Every
measurement below was taken on the **GB10 Spark Grace CPU, cores 10-14 (Cortex-A725), nice 19,
ionice idle**. The programs are single-threaded. No GPU was used.

episodes as targets, with no reward signal, no sampling-based objective and no policy gradient.

The files are regenerated, not committed. Regenerating them with the head-built binary gives
byte-identical files (`cmp`, receipt `data/`). The stdout counters are in
`data/gen-4501-20000.stdout` and `data/gen-4502-1000.stdout`.

Lineage (interface §7) is (generator unit sha256, lineage seed). The generator unit is
`native/omegese45/data/gen.om`. The training lineage used sha256
`2d44ac9c560062e6cd9557393ebe269ab325fdeca03749956f2cbf3637878e58`.
The final source sha256 is `2c61fadcb93d736cfeec894462c84d1053510c4ddf88cb945fb0d3dbf50aebcb`;
the only change is correcting its documentation citation and labeling the outcomes as synthetic.
The lineage seeds are 4501 (train) and 4502 (dev). Each episode is generated by the reference
policy of interface §3 from one goal:

- The goal kind is `mm` or `pair`, each with probability 1/2.
- Each of the three dimensions is drawn independently:
  - 8%: an edge value 0x000, 0x001, 0x100 or 0x101, 2% each;
  - 4%: uniform in 0x101..0xfff;
  - 88%: uniform in 0x001..0x100.
  The admitted range is 1..256, so a dimension is out of range with probability 2% + 2% + 4% = 8%.
- Seeds are uniform in 0..0xffff.
- Each job attempt has a synthetic outcome drawn for training coverage:
  - 55%: `res ok`;
  - 15%: `res fail transport`;
  - 2% each: the 15 other class × code pairs, namely refused × {replay, budget, worker, transport,
    receipt, recomp, verdict, io} and fail × {replay, budget, worker, receipt, recomp, verdict, io}.
- The first `fail transport` of a job is retried once.

These are **grammar-coverage probabilities**, not a measured or predicted runtime distribution.
In particular, `res refused {transport receipt recomp verdict io}` and `res fail {replay budget worker}`
are legal R messages for grammar coverage but unreachable through the Aienet-0 exit map (interface §5).
At run time only that exit map may produce R; the model never produces `res` (interface §0).

Generator stdout begins `oe45gen v1 SEED COUNT`, then 26 coverage counters in this order
(`gen.om`, coverage-line declaration): `mm pair oob retry stop okep e000 e001 e100 e101`,
then `refused replay budget worker transport receipt recomp verdict io`,
then `fail replay budget worker transport receipt recomp verdict io`.

The generator implements the v1.3 episode pin: an out-of-bound G yields only `act refuse bound end`
then `rep refused bound end`. In-bound goals use only A-job/R pairs then P. The core prefix parser
accepts G, G (A-job R)*, or G A-refuse as decode points; it refuses any P inside a prefix, a refuse
after an A or R, and any message after a refuse. Decoding deliberately does not encode this policy
in the message DFA (interface §3); hive must still reject an inappropriate predicted message kind.

## 3. Model

The model is a dense next-token model over the R45 ids. Each position t predicts id[t] from a causal
input built only from ids at positions < t:

- head slot p (0 ≤ p < 30, p < t): the one-hot of id[p], at feature p·41 + id;
- tail slot k (0 ≤ k < 64, k < t): the one-hot of id[t−1−k], at feature (30 + k)·41 + id.

There are (30 + 64) · 41 = 3854 inputs. The longest goal is 30 ids and the longest message 31, so the
head slots cover the whole goal and the 64 tail slots cover the last two messages. The network is one
hidden layer of 256 ReLU units followed by 41 linear outputs, with 3854·256 + 256 + 256·41 + 41 = 997,417
parameters (Wolfram: `3854*256 + 256 + 256*41 + 41 -> 997417`).

- **Initialization (algorithm 1).** splitmix64 seeded with 45 generates W1 and then W2 in payload
  order. Each value is u = ((r >> 40) − 2²³) · 2⁻²³, scaled by 1/8 for W1 and 1/16 for W2. The biases
  are 0. Every value is a dyadic rational and exact in binary32.
- **Loss.** Squared error between the 41 outputs and the one-hot target id[t].
- **Update rule.** Plain SGD, one update per trained position, with learning rate 2⁻⁷ = 0.0078125
  (`lrbits 1006632960`).
- **Phases.**
  - Phase 1 is self-supervised. It trains every position t ≥ 1 of every episode for P1 = 20,000 steps,
    one episode per step, which is one epoch (1,496,027 positions).
  - Phase 2 is supervised. It trains only the positions of messages whose frame id is `act` or `rep`
    (the A/P mask), up to TOTAL = 400,000 steps.
- **Epoch order.** A Fisher-Yates permutation per epoch, drawn from splitmix64 seeded with
  order + 1000003 · epoch (order = 7). It is rebuilt from the step count alone, which is what makes
  resume exact.
- **Decoding.** Greedy argmax.
  - U (unguided) takes the argmax over all ids and validates the message afterwards.
  - G (guided) restricts the argmax to the ids the grammar allows (`ocmask`).

  The decode budget is 31 ids (interface §6).

The step-0 checkpoint is fully determined by (seed 45, algorithm 1). Its payload sha256 is
`6e2e8efebdad7a09535ef0ef7eb90e8cd72a066b693a89e5ebb4da5c32841c1b`, the same in the suite fixture and in
the full run.

### Tests (`tests/omegese45/core/run-core.sh`)

| Check | What fails it |
|---|---|
| gradient check | At three positions of episode 0, central differences (ε = 2⁻⁶) must agree with the backward pass within 0.001 + 0.01·\|g\| at every sampled parameter entry (639 in total; rc 86 otherwise). |
| loss decrease | The summed loss over the first 50 training episodes must fall after one SGD pass over them (rc 87 otherwise). |
| target and mask | The `(episode, t, target, mask)` dump must match `oracle.py mask` byte for byte. |
| causal no-leak | Changing every id at positions ≥ t must not change the output at t, and changing id t must change the output at t + 1 (control). |
| kill -9 and resume | `timeout -s KILL 2` in mid-run, then resuming, must give `ck.a` and `ck.b` byte-identical to an uninterrupted run. |

| round trip | Load then save must reproduce the payload bytes exactly. |

| decode | G on step-0 and trained checkpoints never emits an invalid message. U is invalid (50) or over budget (53) when it should be. A bad prefix or header must exit 40. The refuse prefix must be accepted. |

## 5. Design notes

- **Why not the native tape.** `native/autodiff664/tape.om` at omega-mv `965fb762` (sha256
  `1b4ed431…a708bde`) has these limits: "rank 2 only, at most 32 nodes, 64 elements per node" (line 3),
  and value and gradient arenas of 2048 binary32 each (`global TV f32 2048`, `TG f32 2048`). The first
  weight matrix alone has 3854 × 256 = 986,624 elements. Forward and backward are therefore written out
  in `model.om` and checked against central differences instead. The squared-error loss is the one
  interface §6 names as tape-compatible.
- **Why PACK5 is not reused.** `native/ecosystem5/pack.om` (`docs/ecosystem5/CONTRACT.md`) is
  composed with Omega L775/L776 admission units and pinned to a different compiler (sha256
  `191b776e…98e9`). Its inputs are admitted public examples, not generated episodes. The idea taken
  from it is the supervised-target mask: phase 2 masks the loss to A/P messages (`opmask`).
- **No transformer.** This is a dense model, as interface §6 prescribes for the first step. The
  transformer is NOT_RUN, as stated in §1.
- **Branch base.** `feat/45-pipeline` starts at main `5aaeb65` plus contract `80cc357`. It includes
  only the pipeline commits and the refuse-prefix fix from `00d66c37`. The unused PR #42 merge was
  removed by reconstructing this new branch; the old `feat/45-native-pipeline` is not rewritten.
  PR #42's build/suite convention was consulted, but its code is not a dependency.
- **Dependencies.** `native/omegese45/core/dependencies.json` records:
  - the compiler pin;
  - the SHA-256 unit (omega-mv `bf54b19f`, `om/sha256/sha256-om2.om`, sha256 `dbf002dd…94bb`), used for
    the vocab pin, the data binding and the payload digests;
  - the oracle;
  - each host tool with its version and role.

  The `sed` rewrite of `export fn` to `fn` is the one host step in the build path. Its replacement
  proposal is an omc unit-link mode that accepts exported library units.
